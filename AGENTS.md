# Contribution instructions

- Use the installed official skill-creator and read its current instructions when changing skill structure. Use its initializer/generator where appropriate and quick_validate.py for every changed skill.
- Preserve user instruction priority and task scope.
- Keep SKILL.md concise; move detailed conditional material into linked references.
- Add or update evaluation cases for meaningful behavioral changes.
- Run repository validation, harness tests, and official skill validation before committing.
- Keep generic skills free of domain-specific assumptions; label examples as examples.
- Do not claim performance, novelty, or measured gains without recorded evidence.
- Inspect the final diff for scaffold text, contradictions, broken references, endless reframing, sunk-cost persistence, and metaphor-only transfers.
